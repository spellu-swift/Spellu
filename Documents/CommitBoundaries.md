# 構文解析の確定範囲

本書はInterpreter・Sakuya・Hooriにおける確定範囲の契約をまとめる。
旧Interpreterの評価方式との差も記載する。

## 確定範囲の契約

子の確定範囲は親の現在位置とタグ記録から前方一致し、範囲内の後続まで成立した候補から一つを選ぶ。親に返るのは確定した終了位置、木、タグ記録。親の後続で不一致になれば親の別経路を試せる。子の終了位置や本文の選択を親から選び直すことはできない。

最上位の全体一致では末尾Triviaと実際のEOSを確認する。子は前方一致であり、外側の全体一致のために末尾Triviaや実際のEOSを検査する処理を追加しない。終了位置は元のSourceの絶対UTF-8位置であり、木の末尾とは別に保持する。

## 境界を作る構文

- **Atomic**は本文全体を子として評価する。例えば `P` が `"a"`、`"a" "b"` の順のChoiceOfで、入力が `"abc"` の場合、`Atomic { P }; "c"` は子で `"a"` を選ぶため失敗する。`Atomic { P; "c" }` は子の中で先順位が失敗し、次の候補で成功する。入れ子のAtomicは個別に確定する。

## 記録範囲

`Capture` はタグ記録を保存し、本文の終了位置と木を返す際に入口の記録を復元する。本文の候補を確定する指定とは独立している。Atomicでは成功したタグ記録も親へ返す。タグ記録は文法ごとに分かれる。
