# Hooriエンジン

Hooriは、Earley法で構文解析するエンジンです。
`Spellu(engine: .hoori)` で選択します。

```swift
let parser = try Spellu(engine: .hoori).input(trivia: []) {
    Repeat { Fragment(label: "body", "a") }
    Fragment(label: "tail", "a")
}
let tree = try parser.parse("aaa", strategy: .asis)
```

この例では、反復を2回で終え、後続で最後の `a` を読みます。
同じparserで別の入力を解析するときも、準備済みの文法表を再利用します。
未定義の参照や外部ルールの公開制限は、文法表の準備時に検査します。

## 構成

- `SpelluHoori` は、他のエンジンの実装を呼び出しません。依存先は `Basis`・`SpelluCore`・`SpelluLex` です。
- SyntaxIRは文法表の生成時だけ読みます。解析中は整数の記号IDだけを使います。
- 字句照合はSpelluLexのMomojiriを使います。
- 入力位置、タグ環境、途中結果、診断はパースごとのSessionに分離します。

## 文法表

生成規則の右辺を一つの配列に連結し、項目のドット位置をその添字で表します。
ドットの次の記号は配列の一回の参照で得られます。

| SyntaxIR | 文法表での表現 |
|---|---|
| ルール、`sequence` | 比較範囲を閉じる非終端記号。構文ノードを作る |
| 暗黙の連接 | 右辺の記号列へ平坦化 |
| `choiceOf`、`anyOf` | 本体直下なら生成規則群。入れ子なら順位を外へ渡す補助の非終端記号 |
| `optional` | 本文あり（順位1）と空（順位0）の生成規則を持つ非終端記号 |
| `repeat` | 上限なしの部分は左再帰の非終端記号。必須回数と有限の上限は回数ごとの非終端記号へ展開 |
| `list` | 先頭要素と「区切り＋要素」の反復、任意の末尾区切り |
| `enclosure` | 開始、反復、終了の連接 |
| `token`、`word` | 走査クラスの記号。ラベルとtagは記号の位置ごとに持つ |
| `capture` | 終了時に出力環境を入口の環境へ戻す非終端記号 |
| `atomic` | 子のチャートで評価する境界の記号 |

同じ構文でも、Trivia照合中か診断を抑制するかで動作が変わる場合は、別の非終端記号を作ります。

## 解析

確定範囲ごとに一つのチャートを持ち、位置の小さい順に項目集合を処理します。

- **予測**：非終端記号を待つ項目を呼び出しへ登録します。初めての呼び出しなら、生成規則の初期項目を追加します。
- **走査**：字句を照合して項目を進めます。同じ走査クラスは、同じ位置で一回だけ照合します。Momojiriは終了位置を一つだけ返すので、走査は分岐しません。
- **完了**：生成規則が終わると記号ノードを作り、待っている項目を進めます。

項目は `(ドット位置, 呼び出し, 環境)` で同一性を判定します。同じ項目へ別の導出で至ったときは、リンクを足します。
記号ノードは `(呼び出し, 終了位置, 出力環境)` で一つにまとめ、別の導出は家族として足します。通知はやり直しません。
待ち登録の時点で既存の結果を渡すので、空規則と左再帰に特別な処理は要りません。

字句Triviaだけの文法では、Triviaを字句の照合に含めて項目を増やしません。構文Triviaを持つ文法では、Triviaを読む非終端記号を字句の前に置きます。

## 候補の選択と確定範囲

探索が終わってから、出口の記号ノードから森をたどって候補を選びます。
順位の規則は [Sakuyaの実装](Sakuya.md#共有導出上での選択) も参照してください。

- ChoiceOfは宣言順、AnyOfは指定優先値を使います。
- Optionalは本文を選好し、Repeatはeagerが継続、reluctantが終了を選好します。
- 順位は比較範囲ごとに比較し、反復は先頭の回から比べます。
- 最上位に同値または比較不能な候補が残る場合は `ambiguousPath` を返します。

森全体に導出が一つしかなければ、比較を省いて木だけを組み立てます。
比較範囲を閉じる記号ノードでは、同じ到達の候補のうち厳密に劣るものをその場で捨てます。
比較は最初の差で決まるので、劣る候補を使う導出は、優る候補へ置き換えた導出に必ず負けます。
同値と比較不能な候補は、親の比較で消える場合があるので残します。
導出の循環は、同じルール呼び出しの中で同じノードへ戻ったときに打ち切ります。
空の再帰を含む文法では、打ち切りの位置によってInterpreter・Sakuyaと異なる木を選ぶ場合があります。

Atomicは子のチャートで前方一致し、一件に確定してから親へ返します。
親から子の未選択候補へ戻ることはできません。
同じ境界・同じ位置・同じ環境の結果は再利用します。

## 自動Trivia

構文Triviaが自動で消費した範囲を `SourceTree.trivia` に入力順で返します。
一回の読み飛ばしの中で隣接する範囲は一つの `#trivia` の葉にまとめます。別の読み飛ばしの範囲は、隣接していてもまとめません。
読み方が複数あるときは、先頭から順に各構文Triviaが最も長くなる読み方を採ります。探索が終わってからskipの記号ノードごとに読み方を比べるので、処理順には依存しません。
範囲は順位の比較には使わないので、受理や本文の木は変わりません。
Atomicでは子で確定した範囲を呼び出しの位置に挿入します。

## 上限

上限は `HooriLimits` で与えます。`Spellu.Engine.hoori(limits:)` に渡します。
超えた場合は `safetyStop` を返し、途中の候補を成功として返しません。

| 項目 | 内容 | 既定値 |
|---|---|---|
| `maxTokenRepetition` | 字句の反復回数 | 65,535 |
| `maxBoundaryDepth` | 確定範囲の入れ子の深さ | 1,000 |
| `maxEmptyRepetition` | 必須回数に届くまでに許す無消費の反復の回数 | 1,000 |
| `maxWork` | 一回の解析の総作業量 | 1,000,000 |

総作業量は、項目とリンクとノードの追加、走査クラスの照合、選択の解決と比較、木の具体化を数えます。
数え方はHooriの処理に固有で、他のエンジンの作業量とは対応しません。
長い入力では、`maxWork` を引き上げてください。

## 検証

- `SpelluCompatibleTests`：他のエンジンと同じ期待値で `.asis`・`.compact` の出力を比べます。
- `HooriDifferentialTests`：乱数で作った文法と入力について、Interpreter・SakuyaとHooriの受理・木・エラーを比べます。環境変数 `SPELLU_HOORI_DIFFERENTIAL` で文法の個数、`SPELLU_HOORI_SEED` で乱数の範囲を変えられます。
- `SpelluHooriTests`：文法表の形、Earley法で問題になりやすい文法、上限の動作を確認します。
